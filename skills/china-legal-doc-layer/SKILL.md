# China Legal Doc Layer

## 定位

这是一个**文书层编排 skill**，不是法源数据库，也不是独立法律分析引擎。

它的职责是：
1. 识别用户要生成的文书类型
2. 判断事实和字段是否齐全
3. 在需要时对接 `china-lawyer-analyst` 获取前置分析
4. 把分析结果映射到对应文书模板
5. 输出工作底稿、审稿版或拟正式版

## 与分析基座的关系

- `china-lawyer-analyst`：负责案件识别、法律关系梳理、争议焦点、请求权基础、证据与风险分析
- `china-legal-doc-layer`：负责文书类型路由、字段补全、模板映射、输出控制

除非任务只是纯格式整理，否则**不要跳过分析基座直接硬写文书**。

## 工作流程

按以下顺序执行：

1. **识别文书类型**
   - 读取 `router/document-type-router.md`
   - 判断属于诉讼启动、被动应对、代理意见、程序申请、非诉函件、法律意见、合同审查等哪一类

2. **检查信息完整度**
   - 读取 `router/completeness-check.md`
   - 判断缺失字段是否会影响输出质量
   - 若关键字段缺失，先向用户索要；若可先出底稿，使用统一占位符

3. **对接分析基座**
   - 读取 `bridge/analyst-adapter.md`
   - 将用户输入整理成适合 `china-lawyer-analyst` 的分析任务
   - 目标是拿回结构化分析结果，而不是一大段散文式输出

4. **选择模板并映射**
   - 根据文书类型，读取 `templates/` 下对应模板
   - 把分析结果映射到文书槽位
   - 不要让模型自由发挥到偏离文书规范

5. **按输出等级生成**
   - 读取 `output/draft-levels.md`
   - 默认先给**工作底稿**或**审稿版**
   - 只有在事实较全、风险可控时才输出“拟正式版”

6. **附加风险与法源提醒**
   - 读取 `output/disclaimer-rules.md`
   - 涉及具体法条、司法解释、程序时限、管辖规则时，加入核验提醒

## 文书分类树

完整分类树见：`docs/taxonomy.md`

执行时不需要每次加载全部分类树；仅在以下情况阅读：
- 文书类型不明确
- 用户给的是宽泛目标，如“帮我写个诉讼材料”
- 需要扩展新模板时

## 当前首批模板

优先支持以下模板：
- `templates/litigation/complaint.md` — 起诉状
- `templates/litigation/answer.md` — 答辩状
- `templates/litigation/agent-opinion.md` — 代理意见/补充代理词（通用骨架）
- `templates/procedure/application-general.md` — 程序申请类文书（通用骨架）
- `templates/non-litigation/lawyer-letter.md` — 律师函/催告函/通知函（通用骨架）
- `templates/advisory/legal-opinion-short.md` — 简式法律意见书
- `templates/advisory/contract-review-opinion.md` — 合同审查意见书

## 输出原则

- **先结构，后成文**：先保证槽位完整，再润色表达
- **先分析，后结论**：不要跳过案件分析直接拼文本
- **允许占位，不允许假设**：未知信息使用统一占位符，不擅自编造
- **区分版本**：底稿、审稿版、拟正式版要分开
- **动态法源核验**：静态模板可复用，具体法条有效性应动态确认

## 占位符规范

统一使用：
- `[待补：原告身份信息]`
- `[待补：合同签订日期]`
- `[待补：证据编号与名称]`

不要使用模糊说法，如“某日”“某法院”“相关证据”替代本应明确的信息。

## 不应做的事

- 不把本 skill 当成最终法源库
- 不在事实严重缺失时输出看似完整的正式文书
- 不把分类树全文塞进每次输出
- 不把所有文书模板都塞进主 `SKILL.md`
- 不在没有基座分析的情况下直接给复杂争议写成稿

## 扩展方式

新增文书类型时：
1. 在 `docs/taxonomy.md` 中登记分类位置
2. 在 `router/document-type-router.md` 中增加识别信号
3. 新建对应模板文件到 `templates/` 目录
4. 视需要在 `schemas/` 中补充专属字段
5. 补充 1-2 个示例到 `docs/examples.md`
