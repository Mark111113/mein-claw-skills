# 与分析基座的桥接说明

本文件定义 `china-legal-doc-layer` 如何调用 `china-lawyer-analyst`。

## 目标

文书层不要直接依赖一大段散文式法律分析，而应尽量拿到以下结构化结果：
- 案型识别
- 法律关系
- 争议焦点
- 我方主张 / 对方抗辩
- 证据清单与缺口
- 法律依据候选
- 风险提示
- 程序问题（如有）

## 推荐桥接提示词

当需要调用分析基座时，优先整理成如下任务：

```text
请使用 china-lawyer-analyst skill 分析以下中国法律问题，并以“后续文书起草可直接使用”的方式输出。

【案件事实】
...

【我的身份】
...

【文书目标】
例如：起诉状 / 答辩状 / 律师函 / 法律意见书

【请重点输出】
1. 案型识别
2. 法律关系梳理
3. 争议焦点
4. 我方主张
5. 对方抗辩
6. 关键证据清单及缺口
7. 法律依据候选
8. 程序问题（如有）
9. 风险提示
```

## 何时必须调用基座

以下情况原则上必须先调基座：
- 用户给的是争议事实，不是现成文书槽位
- 涉及复杂合同/侵权/劳动/公司/程序争议
- 需要梳理争议焦点或请求权基础
- 需要对证据与抗辩做结构化分析
- 需要给出法律意见书或诉状底稿

## 何时可弱化调用

以下情况可不必每次完整调用：
- 用户只是让你润色一份现成起草稿
- 用户只是让你规范格式、补标题、整理结构
- 用户已经给了非常完整的文书槽位信息

## 桥接输出要求

从基座拿回结果后，文书层应进行二次整理：
- 不直接原样贴入最终文书
- 先映射到文书字段
- 再控制语气与格式
