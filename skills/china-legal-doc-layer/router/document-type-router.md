# 文书类型路由规则

本文件负责将用户需求映射为**文书类型**。

## 路由步骤

1. 先识别用户是否要“文书成稿/文书底稿/正式法律文本”
2. 再识别属于哪一类文书
3. 若类型不明确，先输出 2-4 个候选并请求澄清
4. 若用户目标明显是正式文本，即使没有明确说“写文书”，也应进入文书层

## 常见触发信号

### 起诉状
触发词：
- 起诉状
- 起诉材料
- 帮我起诉
- 诉讼请求怎么写
- 事实与理由怎么写

### 答辩状
触发词：
- 答辩状
- 回应对方起诉
- 被起诉了怎么答辩
- 逐项回应原告

### 代理意见 / 补充代理词
触发词：
- 代理词
- 补充代理词
- 质证意见
- 庭后意见
- 书面意见

### 程序申请类文书
触发词：
- 申请保全
- 调查取证申请
- 鉴定申请
- 回避申请
- 延期审理申请
- 管辖权异议
- 程序申请

### 律师函 / 通知函
触发词：
- 律师函
- 催款函
- 催告函
- 履约通知
- 解除通知
- 发函给对方

### 法律意见书
触发词：
- 法律意见书
- 给个正式法律意见
- 风险分析报告
- 出顾问意见

### 合同审查意见
触发词：
- 审合同
- 红线修改
- 条款修改建议
- 合同审查意见

## 歧义处理

出现以下情况时，不要立即定稿，先澄清：
- 用户说“帮我写一份材料”，但没说是诉状、答辩还是函件
- 用户说“帮我回复对方”，但不清楚是诉讼内回应还是非诉函件
- 用户给了一大段事实，但没说目标是起诉、答辩、发函还是内部分析

### 建议澄清方式

给出有限候选，不要开放式追问：
- 你更需要的是：1）起诉状 2）答辩状 3）律师函 4）法律意见书？
- 你是想做对外正式文本，还是先做内部工作底稿？

## 默认策略

- 默认优先生成**工作底稿**或**审稿版**，除非用户明确要求正式稿且信息较全
- 涉及复杂争议、程序问题、重大金额时，应先连接分析基座
